# database/

Run these in order (see ../INSTALLATION.md for full details):

1. `00_create_database_and_user.sql` — run as **root**. Creates the
   database and the `library_admin` application user.
2. `01_schema.sql` through `06_seed_data.sql` — run as **library_admin**
   (not root — see the note inside `00_create_database_and_user.sql`
   for why this matters for backups).

Or just run `../scripts/setup_database.sh`, which does all of the above.

## Dataset scale

`06_seed_data.sql` (auto-generated by `generate_seed_data.py` — see that
file for the full generation logic and design notes) seeds:

- 10 categories, 15 publishers, 30 authors, 75 books (real titles/authors/
  publishers/editions, valid checksummed ISBN-13s)
- 150 students (130 active, 12 inactive, 8 blocked)
- 500 issue records — 450 already returned (154 late, with a realistic
  paid/partially-paid/unpaid fine mix) and 50 currently out (35 within
  their loan period, 15 overdue)

To regenerate it (e.g. after tweaking the generator): `python3
generate_seed_data.py`, then reload the database.


## sample_database_dump.sql.gz

A ready-to-import dump of the fully-seeded database (schema + sample
data + views/functions/procedures/triggers), taken with
`scripts/backup_db.sh`. Useful if you'd rather import one file than run
six:

```bash
mysql -u root -p < 00_create_database_and_user.sql
gunzip -c sample_database_dump.sql.gz | mysql -u library_admin -p library_management_system
```
